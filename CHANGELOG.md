# Changelog

All notable changes to this project should be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). **Every release/version must be recorded with its version and date, and all past version sections must be retained** (do not remove or rewrite historical entries except to correct errors). Group entries under `## [Unreleased]` until released, then move them into a dated/versioned heading.

## [Unreleased]

### Changed
- **React SPA scaffold (incremental migration):** added React (`react`, `react-dom`, `react-router-dom`, `@vitejs/plugin-react`) and converted the home entry (`index.html`, `/`, `/index.html`) to a React-rendered app shell (`src/main.jsx`, `src/App.jsx`, `src/components/*`, `src/pages/Home.jsx`). The home route renders the existing home UI and loads legacy page modules after mount to preserve behavior while migration proceeds; routes not yet ported fall back to existing static HTML pages. Vite now uses the React plugin alongside the existing MPA build for remaining pages.
- **Explore route (incremental migration):** added a React route for `/explore` (`src/pages/Explore.jsx`) that renders the existing explore UI and loads legacy page modules after mount (bridge approach) to preserve discovery/search behavior during migration. Existing `explore.html` remains available as a static page.
- **Full SPA route coverage (bridge migration):** added a generic `LegacyHtmlPage` bridge (`src/pages/LegacyHtmlPage.jsx`) and registered React routes for all site HTML pages (clean paths and `/*.html` paths) in `src/App.jsx`, so the React router/app shell now serves the entire site. Legacy pages are loaded as bridged HTML with their scripts executed to preserve existing behavior while migration to native React components continues. Updated Vercel rewrites to send extensionless paths to the React SPA entry (`index.html`) while keeping static assets and `.html` files directly addressable.
- **GitHub Pages deployment:** added `.github/workflows/deploy-pages.yml` to build and deploy `dist/` to GitHub Pages on pushes to `main` (and manual dispatch). Added `postbuild` generation of `dist/404.html` for SPA route fallback on Pages, and made Vite base/router basename configurable via `VITE_BASE`/`import.meta.env.BASE_URL` for project-page and custom-domain deployments.
- **Build/deploy:** introduced a Vite-based production build step for the static multipage site (`package.json`, `vite.config.mjs`-equivalent `vite.config.js`, `.gitignore`). `npm run build` now emits to `dist/` with bundled/minified and fingerprinted JS/CSS assets (`assets/js/*`, `assets/css/*`), code-split chunks, and modulepreload hints in generated HTML.
- **Vercel/caching:** `vercel.json` now builds to `dist/` and serves fingerprinted `/assets/*` as immutable (`max-age=31536000, immutable`) while HTML, `sw.js`, and `manifest.webmanifest` remain revalidated (`max-age=0, must-revalidate`). CSP was updated for bundled app scripts (removed `esm.sh` from script/connect sources).
- **Static assets:** moved public runtime files into `public/` (copied as-is to `dist/`), including `assets/`, `sw.js`, `manifest.webmanifest`, `feed.json`, `craft.json`, `usage.json`, `skills-lock.json`, `logo.png`, and root `theme.css`. Fixed CSS asset references from `../assets/...` to `/assets/...` where needed for the new layout.
- **Supabase bundling:** `js/supabaseClient.js` now imports `@supabase/supabase-js` from npm (bundled by Vite) instead of loading from `https://esm.sh/...` at runtime.
- **Service worker:** rewrote `public/sw.js` for hashed build outputs (runtime caching for versioned app assets, stable-only precache, cache-versioned names, removed esm.sh precaching/handling). Removed duplicate `js/sw.js`.
- **Build compatibility fixes:** corrected broken `js/js/*` script paths in `admin-economy.html`, `contract-center.html`, and `creator-earnings.html`, and added a Vite build hook to copy classic (non-module) local scripts referenced by HTML (e.g. `js/theme.js`, `js/i18n.js`, `test.js`) into `dist/` so existing pages continue to load them.

### Fixed
- Reader: fixed reading appearance/theme selection in the reader controls. Theme cards now use resilient click handling and the reader theme classes/background rules were corrected so choosing Light, Beige, Sepia, Dark, Night, Darkness, Green, Blue, or Custom reliably applies in `reader.html` (`js/reader.js`, `css/reader.css`).

### Added
- Site footer (injected by `js/site-footer.js`): GidiReads column now lists About, Help, Contact, Privacy, and Terms as placeholder items (not linked yet), styled consistently with footer navigation text.
- Root `CHANGELOG.md` as the canonical changelog for the project.
- `AGENTS.md` with repository instructions for AI agents, including the requirement to update the changelog for each version/release.
- “About GidiReads” resource guide on the Resources and Member Resources pages, covering the platform’s story, mission and values.
- Account profile default picture now uses the GidiReads logo from `assets/gidireads-logo.png` when no avatar is set.
- Migration `20261110000000_add_virtual_gifts_and_gift_transactions.sql` adds the missing `virtual_gifts` and `gift_transactions` tables, RLS policies and grants.
- Published chapter counts on story cards across the homepage (featured, trending, recently updated, new releases, continue reading) and on Explore story cards/featured picks, counted from published, non-archived chapters.
- Custom homepage collections now load their selected stories into the section grid (`loadCustomHomepageCollections`), with an empty-state message when a collection has no stories selected.
- Story page “Latest chapter” line now reports whether the most recent chapter event was a publication or an edit, using `published_at`/`updated_at`, instead of only “Last updated”.
- Site language system: English is the base, with French and Russian translations. `assets/language/en.json`, `fr.json` and `ru.json` hold the phrase/attribute mappings, `js/i18n.js` applies them (including dynamically loaded content), a language chooser is injected into the site header, and Settings has a Language card. The choice is persisted in `localStorage` under `gr-site-lang` and more languages can be added by dropping a new JSON file in `assets/language/`.
- `check.md`: manual testing checklist covering every functional area that must pass before the site is considered working (theme, headers, story linking, reader, library, auth, navigation, removed pages).
- Library: long-press on a novel in the library shelf now enters selection mode (checkboxes appear on each novel); selected novels can be removed from the library via a “Delete selected” action bar.
- Reading lists: the list editor (`openListEditor` in `js/reading-lists.js`) now has an optional Cover image URL field that is saved with the list.
- Batch `GidiReads-Launch-2-Batch-4-11` feature port into the current project: library bulk selection toolbar + long-press selection and remove (`js/library.js`, `css/library.css`, `library.html`); reading-list cover upload through the `covers` storage bucket (`js/reading-lists.js`, migration `20261110000001_reading_list_covers.sql`, `storage.buckets` `covers` + owner policies); homepage discovery shelves switched to the `gidireads_novel_rankings` and `gidireads_homepage_shelf` RPCs with direct-query fallbacks (`js/app.js`); admin dashboard access visibility hardened with auth-state refresh and manual hero story selection (`js/admin.js`).

### Fixed
- Site navigation bar: added base `.nav-inner` layout, fixed active underline state for `.nav-links` items, and aligned homepage header styles with the canonical `.nav-links` markup so the nav displays and highlights correctly. The header now reserves space (`body.has-site-nav` padding-top) to prevent overlap and uses a solid background (no transparency/backdrop blur) for clearer separation from page content. Header scripts also apply this spacing/styling support on pages that already include a `.site-nav`, and load `css/rankings.css` so the Rankings button is styled consistently. Header/nav-inner height and spacing are normalized for consistency across pages.
- Reader: `js/theme.js` no longer toggles `body.dark` on the immersive reader (`.reader-body`), preventing site-theme sync from interfering with the reader’s own appearance/theme controls.
- Header unification compatibility: `collection.js`, `moderator.js`, and `holiday-hearts.js` now fall back to canonical header element IDs (`loginBtn`, etc.) so auth controls work with the injected global header.
- Reader: now saves the last-read chapter/novel locally (`localStorage`) and resumes from it when opening a story without a specified chapter (in addition to existing progress/session saving), improving “continue reading” behavior when remote progress is unavailable.
- Story page: `#startReadingBtn` now resumes the user’s last-read chapter for the current story when available (from local reader progress and/or `library_entries.last_chapter_number`) and reflects “Continue Reading”/“Start Reading”/“Read Again” appropriately, including for logged-out users with local progress.
- Explore: story/featured cards now use locally saved last-read chapter progress (when available) to open the reader at the saved chapter and indicate “Continue/Continue reading”, falling back to the story page when no local progress exists.
- My GidiReads: restored/normalized quick-link icons and arrows in the account links grid, and updated the Wallet snapshot balance icons to use the same SVG currency marks as the wallet panel.
- Reader (`story.html` / `js/story.js`): fixed the story page failing to load a story. `story.html` was loading `js/story.js` twice (two different module URLs, so both executed), double-running `initAuth()`/`loadStory()` and attaching listeners twice; the duplicate include is removed. `loadStory()` now retries the story query without the `profiles!` author join if that join fails (matching `explore.js`/`collection.js`), filters out drafts consistently with other reader pages, and the boot IIFE now has a `.catch` so a load error no longer leaves the page stuck on "Loading…".
- Restored characters that were corrupted or dropped to spaces/empties during editing: page titles now use an em dash separator, and icon/arrow/separator glyphs are back on the homepage, auth roles, Authors Studio workspaces, back links, close buttons, share button, and loading placeholders.
- Homepage and Library headers now expose the full primary navigation (Home, Explore, Rankings, Library, The Gathering) instead of only "The Gathering".
- Restored missing Rankings and Notifications links in the headers of Explore, Collection, Author, Story, Reading list, Community, Community space, Analytics, Chapter Editor, Chapter Pricing, and Story Publishing.
- Added `css/rankings.css` to the pages that use the rankings header link so the link is styled and hidden correctly per page.
- The desktop header unread badge now updates together with the bottom-navigation badge.
- Explore's notification badge now uses the shared `nav-badge` class and `navUnreadBadge` id.
- Removed a stray `EOF` marker at the end of `js/settings.js` that threw `EOF is not defined` on the Settings page.
- Removed a leading UTF-8 BOM from `about.html`.
- `account.html`: replaced the incomplete inline theme bootstrap with the standard `data-gr-theme-init` script (sets `data-theme`, `data-theme-name`, `data-site-theme`, color-scheme, font/text-scale, and custom-mode handling consistently), added `js/theme.js` so the theme switcher stays in sync, and included `css/theme-amoled-fixes.css` so AMOLED theme styling applies on this page.
- GitHub Actions workflow `.github/workflows/release-source-zip.yml` to package the repository source as a zip and attach it to a GitHub Release (on release publish or manual run).
- Global footer: the injected `.gr-footer-inner` surface no longer paints a lighter `--surface` background over the footer card, so the footer is one uniform color on dark themes (matching the light-theme behaviour).
- Removed stale references to the deleted information pages (`resources.html`, `reader-resources.html`) from the light-theme stylesheet comment block in `css/theme-light-fixes.css`.
- Admin Creator Economy: the gift catalogue query no longer triggers the global “tables are not installed” warning when only `virtual_gifts` is missing; it now shows a specific “Gift catalogue is not available yet” message.
- Reader (`reader.html` / `js/reader.js`): fixed the reading page failing to open with “We couldn't open this manuscript.” The chapter-end Previous/Next footer had been removed from the reader markup, but `renderChapter()` still dereferenced `#previousBtn`/`#nextBtn` unguarded, throwing `TypeError: Cannot set properties of null` and aborting load before the book was shown. The chapter-end footer with Previous/Next chapter navigation is restored, and the lookups remain guarded for older cached markup.
- Theme: `js/theme.js` is now loaded on `explore.html`, `moderator.html` and `library.html` so the theme switcher (and `theme-sync.js`) works on every public page. All nav bars and headers use `.site-nav` and are recoloured by the CSS custom properties in `css/theme.css` (`--nav-surface`, `--nav-text`, `--nav-accent`, `--page-bg`, …), so one theme change updates every nav bar and header; themes that share a colour reuse the same variable instead of declaring duplicate per-theme fields.
- Story page (`js/story.js`): ported the batch build's robustness fixes — story-like button state (`story_likes`) with live count updates, story query retries that drop the `profiles!` author join when the relationship fails, recommendation fallbacks that fetch author metadata without that join, and “See all” links that route to the matching collection page instead of a bare explore anchor.

### Changed
- `docker-compose.yml`: bind-mount the repository into nginx's web root (`/usr/share/nginx/html`) so local file edits are served immediately without rebuilding; make `.env` optional for port overrides (`PORT`, default `8080`).
- Unified similar site headers to use the canonical injected header (`js/site-header.js`) with consistent position and elements across main pages (excluding author view and community), replacing their hardcoded `.site-nav` blocks. The canonical header uses the compatible `navAdminLink` admin control id.
- Synced site nav bars/headers and the shared redesigned footer with theme tokens (`--nav-surface`, surface/text/accent/line colors) so they adapt to the selected theme and fit the page. Removed hardcoded nav/footer overrides on library/home/explore that prevented header and footer colors from following the active theme consistently.
- Canonical/global header (`js/site-header.js`) restored to the standard site navigation structure (Home, Explore, Rankings, Library, The Gathering links; Rankings shortcut, search, notifications, profile, admin, login actions) so pages using the injected header share the intended global header. It now syncs header auth state (login button text, admin-only visibility of the Admin Dashboard link) and defaults the login button to "Log in". Box-like elements in header nav actions (buttons and search) have rounded corners consistently. Duplicate Rankings/Search shortcut elements were removed from header actions (they are already available in the primary navbar). Global header primary navbar updated to remove Home/Explore/Library and keep The Gathering; notifications button removed. Rankings nav-link button added consistently in header actions across global-header pages, with overrides to ensure it remains visible in the global header on home/index, explore, and library. Search action link (`home-nav-search`) added to global header actions on all global-header pages.
- `Dockerfile`: clarified the nginx configuration comment.
- `test.html` / `test.js`: redesigned the local page inspector (`/test.html`) to be manageable — select specific pages or all/filtered/none, then load the selected set into an iframe grid, open in tabs, or preview individually (no longer auto-loads every page). Added viewport size controls (responsive or preset/custom width × height) to resize loaded preview/grid iframes for inspection.
- `js/theme.js`: limited the quick theme toggle (footer/logo and other `data-theme-toggle` controls) cycle to **Dark → Beige → AMOLED** to avoid cycling into unconfigured/extra themes (e.g. Custom); all themes remain selectable in Settings.
- Headers unified: `collection.html`, `moderator.html`, `library.html`, `terms.html`, `story.html`, `reading-list.html`, `people.html`, `notifications.html`, `my-gidireads.html`, `holiday-hearts-entry.html`, `holiday-hearts.html`, `explore.html`, `creator-earnings.html`, `author.html` and `account.html` now share the same canonical site header (brand + primary navigation + rankings/notifications/profile/login actions, current page highlighted) matching `index.html`. `library.html` and `index.html` inject this header via `js/site-header.js`. Authors Studio pages (`chapter-pricing.html` and siblings) keep their own studio shell.
